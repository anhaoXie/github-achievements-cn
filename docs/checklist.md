# 领取自查清单

做完操作后，按这份清单逐项确认，能排掉 90% 的「徽章不出现」问题。

## 1. 操作层面

- [ ] 操作发生在**公开仓库**（不是私有仓库）
- [ ] 操作发生在**正常仓库**（不是 fork 出来的仓库内部）
- [ ] 合并 / 关闭的目标是**默认分支**（`main` / `master`）
- [ ] 提交作者邮箱已在 GitHub 账号里**验证并关联**
- [ ] 需要 review 的徽章确认**确实没有 review 记录**（YOLO）

## 2. 逐徽章确认

| 徽章 | 确认点 |
| --- | --- |
| 🦈 Pull Shark | PR 已合并进默认分支；是你的 PR；至少 2 个 |
| ⚡ Quickdraw | 关闭时间距创建时间 < 5 分钟；issue 或 PR 均可 |
| 😅 YOLO | 自己的 PR；无任何 review；已合并 |
| 🤝 Pair Extraordinaire | 提交里有 `Co-authored-by:`；对方邮箱对应 GitHub 账号；PR 已合并 |
| 🧠 Galaxy Brain | 回答出现在 Discussions；已被提问者/维护者**采纳**；至少 2 个 |
| ⭐ Starstruck | 你创建的仓库；star ≥ 16 |
| ❤️ Public Sponsor | GitHub Sponsors 赞助成功（任意金额） |

## 3. 时间与显示

- [ ] 距离操作完成已过 **24 小时**（统计有延迟）
- [ ] 用无痕窗口打开个人主页，排除缓存
- [ ] 直接访问 `https://github.com/<用户名>?tab=achievements`
- [ ] 设置里没有关闭 `Show Achievements on my profile`

## 4. 验证触发的方法

1. 打开个人主页，鼠标悬停徽章 → 弹窗显示解锁时间和 `History` 记录。
2. 弹窗底部会列出触发事件（例如 YOLO 显示 `Merged without a review`）。
3. 多次操作只会更新计数，不会重复列事件（一次性成就只记一次）。

## 5. 记录表模板（建议每个都记）

```markdown
| 徽章 | 目标动作 | 完成时间 | 是否出现 | 出现时间 |
| --- | --- | --- | --- | --- |
| YOLO | 合并无 review 的自有 PR | 2026-11-01 | 是 | 2026-11-01 |
| Quickdraw | 5 分钟内关闭 issue | 2026-11-01 | 否 | 待 24h |
```

## 6. 常见误判

- **在 fork 里开 PR 给自己仓库合并**：多数情况下不计数，要合入上游仓库。
- **PR 合并到非默认分支**：不计数。
- **私有仓库的合并**：不保证统计，用公开仓库复现。
- **拿过一次性成就**：Quickdraw / YOLO 不会第二次出现，不是 bug。
